# 3D models: the catalogue

Every 3D object the engine can place, where it comes from, and how it reaches the game. Units: 1 = one hex radius
(a human is 2.65 units, ~0.68 m). The engine scales each model uniformly so its height equals the catalog `height`
and stands it with its base centred on the anchor hex (MapStage::placeModels, Engine2's models.ts rule).

## Pipeline

1. **Source**: a GLB (textures embedded). Engine2's own are in `C:/Engine2/public/game/models` and `.../props`
   (read-only). EmberEngine's are built here: `content/models/<kit>/<name>-vNN.glb` + `.blend` (versioned: a change
   is a new version, never an overwrite), generated by `content/models/blender/kit_<kit>.py` (headless Blender 5.2,
   shared library `emberlib.py`; photo textures = `textures/*.jpg`, downscaled Engine2 assets, see `textures/README.md`).
   ```
   blender -b --python content/models/blender/kit_forest.py            # every asset of the kit
   blender -b --python content/models/blender/kit_forest.py -- stump   # one asset
   blender -b <Meshy .blend> --python content/models/blender/export_hearth.py
   ```
2. **Staging + cook**: the mesh pack is cooked from one folder, so the sources are copied into
   `build/meshes/src-v2/` (`models/`, `props/` = Engine2's GLBs; `ember/<kit>/` = this folder's GLBs), then
   `Cooker meshes build/meshes/src-v2 build/meshes/props-v2.pak --cache build/meshes/cook-cache`
   (the cache is keyed by file bytes: Engine2's 15 come back from the cache). `props.pak` (the old pack) is untouched.
3. **Catalog**: `models.json` (this folder) lists EmberEngine's models (id `ember-*`, Portuguese name, file, authored
   height/width, footprint one/pair/triple, editor section, blocks movement). `python -I
   tools/scripts/models/catalog_models.py` merges them into `content/engine2/editor-catalog.json` (decorations of the
   model kind + the editor's 3D palette); run it again whenever `export_editor_catalog.ts` regenerates that file.
   Engine2's own 3D decorations (`tree-3d-*`, `prop-3d-tavern-*`, `rocks-3d-grey-outcrop`) are already there.
4. **In the game**: `--meshes build/meshes/props-v2.pak` (JOGAR.bat). The Map Editor's 3D palette places any
   `ember-*` id; `tools/scripts/models/make_showcase_draft.py` writes a draft showing one of each.

## Checks

- `Sandbox --meshes build/meshes/props-v2.pak --grid 8 --capture captures/models/NNN.png` (every mesh on a grid at
  scale 1: import, orientation, materials).
- `Sandbox --title-screen test-editor --map-ui <showcase draft> ... --capture` (the models on a real map, lit).

The extra kit (`blender/kit_extra.py`, 2026-10-16): the sprint's extra list, all 12 built. Gotcha found there: a boolean cut
(groove) on an already subdivided + displaced slab collapsed the mesh to 3 vertices with the exact solver; cut first,
subdivide after. Object `scale` acts in the object's own frame before its rotation (a torus turned on its side scales
along world z through local x). Captures (local, git-ignored): `captures/models/005` (release) and `006` (debug +
validation, exit 0) = the Map Editor showcase of all 47 models on aldeia015.
